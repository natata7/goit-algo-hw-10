
# Задача 1. Порівняльний аналіз жадібного алгоритму та динамічного програмування

В рамках домашнього завдання було реалізовано та протестовано два підходи до розв'язання задачі про видачу решти для касового апарату за набору монет `[50, 25, 10, 5, 2, 1]`.

Обидві функції приймають суму та повертають словник, у якому ключами є номінали монет, а значеннями — їхня кількість.

Для суми 113 обидва алгоритми повертають однаковий набір монет:

```python
{
    50: 2,
    10: 1,
    2: 1,
    1: 1
}
```

Загальна кількість монет — 5.

## Продуктивність та поведінка при великих сумах

Жадібний алгоритм (`find_coins_greedy`) послідовно вибирає найбільший номінал монети, який не перевищує залишок суми.
Часова складність: O(N), де N — кількість номіналів монет.
Просторова складність: O(N) у найгіршому випадку для словника результатів.

* Висока швидкість виконання.
* Низьке споживання пам'яті.
* Простота реалізації.
* Не гарантує мінімальну кількість монет для довільних наборів номіналів.

Алгоритм динамічного програмування (`find_min_coins`) перевіряє можливі комбінації монет для кожної проміжної суми та знаходить варіант із мінімальною кількістю монет.
Часова складність: O(A × N), де A — задана сума, N — кількість номіналів.
Просторова складність: O(A).

* Не залежить від того, чи є набір номіналів оптимальним для жадібного підходу.
* Продуктивність знижується зі збільшенням суми.
* Потребує більше часу для обчислень.
* Використовує додаткову пам'ять для збереження проміжних результатів.

## Висновки

Для заданого набору монет `[50, 25, 10, 5, 2, 1]` жадібний алгоритм є більш ефективним з погляду швидкості виконання та використання пам'яті. Це пов'язано з тим, що набір номіналів дозволяє знаходити оптимальну кількість монет жадібним способом. Тому немає потреби перевіряти всі можливі комбінації.

Алгоритм динамічного програмування має більшу обчислювальну складність, але гарантує мінімальну кількість монет навіть для наборів номіналів, де жадібний підхід не працює оптимально (наприклад, `[4, 3, 1]` і потрібно видати суму `6`).

Для касової системи з фіксованим набором номіналів доцільно використовувати жадібний алгоритм, оскільки він забезпечує швидку видачу решти навіть для великих сум.

# Задача 2. Дослідження точності методу Монте-Карло для обчислення визначеного інтеграла

Метод Монте-Карло базується на генерації випадкових точок у прямокутній області [a, b]. Площа під кривою обчислюється як відношення точок під графіком до загальної кількості згенерованих точок N.

1. Метод Монте-Карло показує високу точність наближення. Зі збільшенням кількості випадкових точок $N$ результат ймовірнісно збігається до точного значення 2.666667. Похибка методу Монте-Карло зменшується зі швидкістю $O(1 / \sqrt{N})$.

2. Порівняння алгоритмів:
   * **`scipy.integrate.quad`** розраховує значення за декілька мікросекунд з точністю майже до рівня машинного нуля (похибка $10^{-14}$).
   * Метод Монте-Карло потребує значно більше обчислювальних ресурсів для досягнення високої точності, але є незамінним для обчислення багатовимірних інтегралів або складних областей інтегрування, де квадратурні формули стають неефективними.

3. Підсумок:
   Розрахунки повністю підтверджують коректність роботи реалізованого методу Монте-Карло для знаходження площі під кривою.
